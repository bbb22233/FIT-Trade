# P1-003 — PostgreSQL persistence and atomic business effects

## Identity

- Task ID: `P1-003`
- Owner: server root Codex
- Branch: `codex/p1-postgres-persistence`
- Base: exact accepted P1-002 commit

## Objective

Make PostgreSQL the authoritative source for identity, ownership, operations,
orders, Inbox, Outbox, and audit facts, with atomic and recoverable effects.

## Owned paths

- Allowed: `services/trading-core/**`, `infra/postgres/**`
- Read-only: `contracts/**`, `docs/**`, `coordination/**`, root `AGENTS.md`
- Forbidden: `services/hermes-agent/**`, `services/hyperliquid-adapter/**`,
  other `infra/**`

## Deliverables

- Versioned forward-compatible migrations and checksum manifest
- PostgreSQL repository and transaction implementations
- Ownership-preserving primary, unique, foreign-key, and check constraints
- Atomic Operation/Order plus Outbox plus required AuditEvent writes
- Inbox deduplication and aggregate-version compare-and-swap
- Migration, rollback-compatibility, and crash-injection test harness

## Acceptance checks

- Tests run against a real disposable PostgreSQL instance, not SQLite or a mock.
- A process crash before or after each named statement/commit boundary produces
  either the complete effect or no effect.
- Duplicate requests, event IDs, attempt IDs, client order IDs, and Inbox
  deliveries cannot produce duplicate effects.
- Cross-user/account foreign-key substitution, direct SQL mutation, and
  identifier enumeration fail closed.
- Database roles are least-privilege; the application role cannot bypass
  ownership enforcement or administer PostgreSQL.
- Concurrent updates preserve monotonic aggregate versions and reject lost
  updates.
- Migrations are repeatable from empty, upgrade from the accepted predecessor,
  and leave prior readers compatible during the defined window.
- Database logs, errors, fixtures, and test output contain no secrets.

## Hard boundaries

- Disposable local/server development PostgreSQL only.
- No public database port, production data, exchange access, wallet, signer,
  deployment, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
