## Objective

Implement the smallest Go platform layer that authenticates synthetic
development users, authors identity on the server, and enforces session, device,
ownership, internal-tool, and idempotency rules without a database or exchange.

## Owned paths

- Allowed: `services/trading-core/**`

## Deliverables

- Bounded loopback-only HTTP API and a concrete WebSocket authorization harness
- Enumeration-resistant login, Argon2id password verification, session issuance,
  rotating refresh family, expiry, rotation, fixation defense, and revocation
- Password-authorized new-device enrollment, server-generated device identity,
  globally unique Ed25519 public-key ownership, proof-of-possession, first
  session issuance, key revocation, signed Challenge verification,
  action/payload binding, and single-use consumption
- Server-authored HTTP, WebSocket, and internal-tool request contexts that
  cannot be overridden by bodies, headers, query values, model output, or MCP
  arguments
- Independent account/source exponential login throttles and exact general API
  and WebSocket limits from the frozen execution plan
- Storage, clock, entropy, nonce, transaction, AuditIntent, and
  NotificationIntent interfaces
- In-memory fakes used only by tests and visibly marked non-production

## Acceptance checks

- `gofmt`, `go vet`, unit tests, and race tests pass.
- Token entropy, digest-only storage, access/refresh expiry, rotation, refresh
  reuse, fixation, logout, session revocation, device revocation, and Ed25519
  verification match the frozen contract.
- A planted pre-authentication session cannot survive login or a privilege
  transition. The old ID and token family are rejected after rotation.
- Reuse of any refresh token revokes and rejects every already-issued descendant
  in that family, including a chain at least four rotations deep.
- New-device and lost-device enrollment require a correct password and valid
  one-time proof-of-possession. Device creation plus first session is atomic;
  duplicate key, wrong owner, cross-account rebind, replay, concurrent reuse,
  client-selected device/owner ID, and revoked key fail closed.
- Revocation denies HTTP, established WebSocket, new WebSocket, refresh, and
  internal-tool ingress within 5 seconds.
- Cross-user/account/object-ID mutation cannot read or modify another owner.
- HTTP and MCP/tool inputs containing server-owned identity or authorization
  fail closed before business logic.
- Challenges bind every frozen field; invalid signature, revoked key, replay,
  mismatch, expiry, concurrent double use, or clock-boundary ambiguity fails.
- Independent account and source failure sequences enforce 1/2/4/8-second
  backoff and the fifth-failure lock atomically. Distributed-source,
  shared-source, reset, expiry, concurrency, and generic-response cases pass.
  Every lock creates both AuditIntent and internal NotificationIntent.
- Concurrent identical requests produce one logical effect; conflicting
  idempotency reuse is rejected.
- Request size, field/list bounds, content types, deadlines, every frozen HTTP
  and WebSocket rate/burst/concurrency boundary, slow clients, WebSocket
  reauthorization, and disconnect cleanup are tested.
- AuditIntent is immutable and complete enough for P1-004 to materialize the
  exact AuditEvent in the same PostgreSQL transaction as the business effect.
- NotificationIntent is internal-only and complete enough for P1-004 to persist
  it transactionally without any external delivery capability.

## Hard boundaries

- Test listeners bind loopback only and close within the test.
- Synthetic credentials remain test-only and never appear in logs.
- No persistent credential, public listener, database, NATS, exchange SDK,
  signer, wallet, deployment, production, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
