must share before platform implementation starts.

## Deliverables

- User, device, session, account-ownership, device-challenge, request-envelope,
  event-envelope, Inbox, Outbox, AuditIntent, and AuditEvent contracts
- Exact token, revocation, Challenge TTL, Ed25519 signature, login throttle, and
  device-key revocation semantics from `coordination/PHASE1_EXECUTION.md`
- Explicit server-authored identity and transaction-boundary rules
- Idempotency key scope, canonical request digest, and conflict behavior
- Event subject, stream, owner scope, ordering, redelivery, and compatibility
  rules
- PostgreSQL ownership, referential-integrity, migration, Outbox retention, and
  recovery invariants
- Failure-injection matrix covering every statement, commit, publish, and ack
  boundary
- Recovery evidence schema freezing workload ID/hash, fixed seed, event rate,
  UTC clock source, failure timestamp, last committed/recovered sequence, RPO
  calculation, restore start/end events, RTO calculation, versions, and hashes
- Positive, negative, replay, expiry, cross-owner, and malicious-input fixtures
- File manifest proving existing Phase 0 contract semantics are unchanged

## Acceptance checks

- Existing Phase 0 tests plus the new platform verifier pass from `npm test`.
- Platform schemas accept every valid fixture and reject every negative fixture.
- Client-supplied identity, ownership, authorization, server time, token digest,
  and device-verification fields are rejected where the server owns them.
- A reused idempotency key with a different canonical request fails closed.
- Challenge, token, refresh rotation, revocation, device signature, throttle,
  compatibility, retention, and recovery rules are executable and use the
  frozen values.
- MCP/tool inputs still cannot carry user, account, session, confirmation, or
  device-verification authority controlled by a model.
- Inbox/Outbox rules identify the single PostgreSQL transaction that owns each
  business effect, immutable audit event, and deduplication record.
- Event envelopes bind user and account scope, stable event ID, aggregate ID and
  version, causation, correlation, schema version, and payload digest.
- Recovery evidence cannot present target RPO/RTO as measured results.
- Diff and object checks prove all non-manifest Phase 0 contract files are
  byte-identical to the base.
