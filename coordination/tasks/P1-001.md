# P1-001 — Platform contract and failure-semantics foundation

## Identity

- Task ID: `P1-001`
- Owner: local Codex coordinator
- Branch: `codex/p1-platform-contracts`
- Base: exact accepted Phase 1 task-packet commit

## Objective

Freeze the semantics that Go, PostgreSQL, NATS, clients, and recovery tooling
must share before platform implementation starts.

## Owned paths

- Allowed: `contracts/**`
- Read-only: `docs/**`, `coordination/**`, root `AGENTS.md`
- Forbidden: `services/**`, `infra/**`

## Deliverables

- User, device, session, account-ownership, device-challenge, request-envelope,
  event-envelope, Inbox, Outbox, and audit contracts
- Explicit transaction-boundary and server-authored identity rules
- Idempotency key scope and conflict behavior
- Event subject, stream, ordering, redelivery, and compatibility rules
- PostgreSQL ownership, referential-integrity, migration, and recovery
  invariants
- Failure-injection matrix covering every commit/publish/ack boundary
- Positive, negative, replay, expiry, cross-owner, and malicious-input fixtures

## Acceptance checks

- Contract tests accept every valid fixture and reject every negative fixture.
- Client-supplied `user_id`, `account_id`, ownership, authorization, and
  server-time fields are rejected where identity must come from the session.
- A reused idempotency key with a different canonical request fails closed.
- Session revocation and device-challenge consume/expiry semantics are
  unambiguous and executable.
- Inbox/Outbox rules identify the single PostgreSQL transaction that owns each
  business effect and audit record.
- Event envelopes contain stable event IDs, aggregate versions, causation,
  correlation, and schema versions without carrying secrets.
- Recovery evidence records observed values and cannot present target RPO/RTO
  as measured results.
- Existing Phase 0 contract tests and language consumers remain green.

## Hard boundaries

- No service implementation, database, NATS server, deployment, network
  listener, exchange access, wallet, or signer.
- No real user, account, device, credential, or server identifiers in fixtures.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
