## Objective

Create reproducible, default-disabled development infrastructure and prove that
PostgreSQL and derived NATS state recover without enabling trading.

## Owned paths

- Allowed: `infra/**`
- Read-only: `contracts/**`, `services/**`, `docs/**`, `coordination/**`,
  root `AGENTS.md`
- Forbidden: application or contract changes

## Deliverables

- Pinned local Docker and Linux systemd development skeletons
- Authenticated, private PostgreSQL, NATS, and OpenTelemetry configuration
- PostgreSQL base-backup, WAL-archive, restore, verification, and retention tools
- NATS rebuild-from-Outbox procedure and verification tool
- Immutable version manifest, health checks, rollback notes, and evidence report
- Frozen synthetic recovery workload and failure schedule

## Acceptance checks

- Services are disabled by default. Disposable starts bind only loopback or an
  internal container network and expose no public socket.
- Runtime egress is deny-by-default. Tests reject DNS and TCP access to public
  and exchange endpoints; only explicitly named internal development peers are
  reachable.
- PostgreSQL and NATS require authentication and do not use default credentials.
- No connector, executor, signer, exchange SDK, wallet, live-account setting,
  order subject, or corresponding systemd/container unit exists.
- Infrastructure contains no credential values; restricted runtime injection
  fails closed when absent.
- A clean development host creates the stack reproducibly from pinned versions.
- Restore starts with every trading/execution capability absent.
- Point-in-time recovery verifies constraints, aggregate versions, complete
  Outbox continuity, audit linkage, and fixture checksums.
- The recovery run uses the frozen seed, event rate, UTC clock, failure point,
  and evidence schema. RPO derives from last committed versus last recovered
  sequence/time; RTO runs from restore invocation until all verification gates
  pass.
- Backup corruption, missing WAL, incompatible migration, partial restore,
  missing credentials, and external egress fail closed.
- If recovery requires a service or contract change, this task stops and emits
  a bounded remediation proposal. It cannot edit the read-only path, and P1-007
  remains blocked until the remediation is accepted as a new descendant.

## Hard boundaries

- No deployment to a production path, no service enable/start outside the
  disposable harness, and no off-site credential configuration.
- No exchange access, wallet, signer, live account data, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
