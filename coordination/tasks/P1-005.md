# P1-005 — Default-disabled infrastructure, backup, and recovery proof

## Identity

- Task ID: `P1-005`
- Owner: server root Codex
- Branch: `codex/p1-recovery-infra`
- Base: exact accepted P1-003 and P1-004 commits

## Objective

Create reproducible, default-disabled development infrastructure and prove that
PostgreSQL and NATS-derived state can be recovered without enabling trading.

## Owned paths

- Allowed: `infra/**`
- Read-only: `contracts/**`, `services/**`, `docs/**`, `coordination/**`,
  root `AGENTS.md`
- Forbidden: application or contract changes

## Deliverables

- Pinned local Docker and Linux systemd development skeletons
- Private-network PostgreSQL, NATS, and OpenTelemetry configuration
- PostgreSQL base-backup, WAL-archive, restore, verification, and retention tools
- NATS rebuild-from-Outbox procedure and verification tool
- Immutable version manifest, health checks, rollback notes, and recovery report
- Synthetic end-to-end recovery drill with observed RPO/RTO

## Acceptance checks

- Every service is disabled by default and binds no public port.
- Infrastructure contains no credential values; secret inputs use documented
  restricted files or runtime injection and fail closed when absent.
- A clean host can create the development stack reproducibly from pinned
  versions.
- Restore starts with all trading/execution capability absent or disabled.
- Point-in-time recovery verifies row counts, constraints, aggregate versions,
  Outbox continuity, audit linkage, and fixture checksums.
- The recovery report distinguishes targets from observed RPO/RTO and records
  timestamps, versions, hashes, and unresolved gaps.
- Backup corruption, missing WAL, incompatible migration, and partial restore
  fail closed with actionable diagnostics.
- Shell, configuration, dependency, secret, and exposed-port checks pass.

## Hard boundaries

- No actual deployment to a production path, no service enable/start outside a
  disposable development harness, and no off-site credential configuration.
- No exchange access, wallet, signer, live account data, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
