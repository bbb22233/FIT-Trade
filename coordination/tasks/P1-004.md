## Objective

Make PostgreSQL authoritative for identity, ownership, operations, orders,
Inbox, Outbox, and audit facts, with atomic and recoverable effects.

## Owned paths

- Allowed: `services/trading-core/**`, `infra/postgres/**`
- Read-only: `contracts/**`, `docs/**`, `coordination/**`, root `AGENTS.md`
- Forbidden: `services/hermes-agent/**`,
  `services/hyperliquid-adapter/**`, other `infra/**`

## Deliverables

- Versioned expand/contract migrations and checksum manifest
- PostgreSQL repositories and transaction implementations
- Ownership-preserving primary, unique, composite foreign-key, row-security,
  and check constraints
- Atomic business effect plus Outbox plus immutable AuditEvent writes
- Transactional internal Notification records and notification Outbox events
- Transactional Inbox deduplication and aggregate-version compare-and-swap
- AuditIntent-to-AuditEvent mapping with field-parity tests
- NotificationIntent-to-Notification mapping with field-parity tests
- Migration, predecessor-compatibility, role, and crash-injection harness

## Acceptance checks

- Tests run against a real disposable PostgreSQL instance, not SQLite or a mock.
- Crash before and after every frozen statement and commit boundary produces the
  complete effect or no effect, including AuditEvent, Notification, and Outbox.
- Duplicate request, event, attempt, client-order, and Inbox IDs cannot produce
  duplicate effects.
- Cross-user/account foreign-key substitution, row-policy bypass, direct SQL
  mutation, identifier enumeration, and wrong-owner AuditIntent fail closed.
- Application and migration roles are separate and least-privilege; the
  application cannot disable row security or administer PostgreSQL.
- Concurrent updates preserve monotonic aggregate versions and reject lost
  updates.
- Migrations work from empty and from the accepted predecessor. Expand changes
  keep the current and immediate previous application version compatible;
  destructive cleanup is forbidden in Phase 1.
- Phase 1 Outbox business events cannot be deleted, truncated, or cascaded.
- Database logs, errors, fixtures, and test output contain no secrets or
  plaintext tokens.
- AuditEvent preserves the frozen actor, request, causation, correlation, owner,
  session, event, and payload-digest links. Notification remains internal and
  has no external destination or credential.

## Hard boundaries

- Disposable development PostgreSQL only, authenticated and non-public.
- No production data, exchange access, wallet, signer, deployment, production,
  or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
