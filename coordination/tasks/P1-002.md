# P1-002 — Go API, identity, session, and ownership foundation

## Objective

Implement the smallest Go platform layer that authenticates a synthetic
development user, authors request identity on the server, and enforces session,
device, ownership, and idempotency rules without a live database or exchange.

## Owned paths

- Allowed: `services/trading-core/**`
- Read-only: `contracts/**`, `docs/**`, `coordination/**`, root `AGENTS.md`
- Forbidden: `services/hermes-agent/**`, `services/hyperliquid-adapter/**`,
  `infra/**`

## Deliverables

- Bounded HTTP API and middleware with input-size, timeout, and rate-limit hooks
- User, device, session, account-ownership, and device-challenge domain logic
- Server-authored request context that cannot be overridden by request bodies
- Session revocation and one-time challenge consumption
- Storage, clock, nonce, and transaction interfaces for deterministic tests
- In-memory fakes used only by tests and visibly marked non-production
- Structured errors, audit intents, and OpenTelemetry-compatible correlation

## Acceptance checks

- `gofmt`, `go vet`, unit tests, and race tests pass.
- Cross-user/account/object-ID mutation cannot read or modify another owner.
- Request bodies containing server-owned identity or authorization fields fail
  closed.
- Revoked sessions fail on HTTP and streaming authorization paths.
- Device challenges are bound to user, device, session, action, nonce, and
  expiry; replay, mismatch, or double consumption fails.
- Concurrent identical requests produce one logical effect; conflicting reuse
  of an idempotency key is rejected.
- Bounds are tested for request size, field length, list size, deadlines, and
  malformed content types.
- No financial float fields, secrets, exchange SDK, signer, or network write
  capability are introduced.

## Hard boundaries

- Test listeners may bind loopback only and must close within the test.
- No persistent production credentials, public listener, database deployment,
  exchange call, wallet, signer, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
