## Objective

Implement and accept the Go consumer of the frozen Phase 1 platform contracts
before any API, authentication, database, or messaging implementation starts.

## Owned paths

- Allowed: `services/trading-core/platformcontract/**`
- Read-only: every other `services/trading-core/**`, `contracts/**`, `docs/**`,
  `coordination/**`, root `AGENTS.md`
- Forbidden: `services/hermes-agent/**`,
  `services/hyperliquid-adapter/**`, `infra/**`

## Deliverables

- Strict Go platform types and validators generated or mechanically mapped from
  the accepted contracts
- Unknown-field, null, numeric coercion, timestamp, UUID, enum, bounds,
  owner-scope, and malicious-input rejection
- Event and request canonical digest implementations
- Device-enrollment, notification, AuditEvent causation, and login-throttle
  contract mappings
- Frozen valid/negative fixture and recursive differential test harness
- Reproducible generation or mapping command with drift detection

## Acceptance checks

- `gofmt`, `go vet`, unit tests, and race tests pass.
- Go validates every frozen platform fixture with the same result as the Node
  contract verifier.
- Every schema field is mapped or explicitly proven transport-only; additions,
  removals, or type drift fail the build.
- Server-owned and model-forbidden fields cannot be populated by untrusted
  decode paths.
- Canonical request and payload digests match shared golden vectors and change
  for every bound-field mutation.
- Enrollment proof, refresh-family descendants, AuditEvent linkage,
  Notification, and each rate-limit boundary match Node fixture results.
- No HTTP listener, authentication store, database driver, NATS client,
  financial float, exchange SDK, signer, or network write is introduced.

## Hard boundaries

- Contract consumption only; no service behavior or infrastructure.
- No secret, wallet, exchange, deployment, production, or automatic trading.
- `MERGE/DEPLOY/PRODUCTION AUTHORIZED = NO`
