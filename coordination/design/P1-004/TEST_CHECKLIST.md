# P1-004 PostgreSQL persistence acceptance checklist

## 1. Harness contract

The future P1-004 implementation must provide the following deterministic,
non-production commands.  Each command provisions an authenticated disposable
PostgreSQL 16.x instance, uses synthetic fixtures only, writes a machine-readable
artifact keyed by `EVIDENCE_ID`, and exits non-zero on a missing probe,
unexpected result, leaked secret, or skipped assertion.

```text
make p1-004-verify EVIDENCE_ID=<ID> CASE=<case>
make p1-004-migration-verify EVIDENCE_ID=<ID> CASE=<case>
make p1-004-fault-verify EVIDENCE_ID=<ID> WORKFLOW=<workflow> CUT=<cut>
make p1-004-secret-scan EVIDENCE_ID=<ID>
make p1-004-scope-check EVIDENCE_ID=<ID>
```

`p1-004-fault-verify` expands the accepted
`failure-injection-v1.json` matrix and fails if a statement/commit/publish/ack
cut is absent.  Commands below are acceptance commands, not commands executed
by this design-only task.  The expected artifact contains baseline/candidate
commit, engine version/image digest, UTC timestamps, fixture hash, command,
observed result, row-count assertions, and redacted error classification.

## 3. Completion rule

Acceptance requires every evidence ID above to be present exactly once, pass on
a real disposable PostgreSQL instance (not SQLite/mock), and include a redacted
artifact hash. `SKIPPED`, missing artifact, mocked database, undeclared
environment limit, or a command that does not execute its named oracle is a
failure, not PASS. A green subset, passing unit tests, or successful migration
does not authorize merge, deployment, production, wallet/signer use, exchange
access, automatic trading, or live orders.
