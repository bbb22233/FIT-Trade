# 完整产品需求

## 1. 产品愿景

构建一个个人专属的交易 Agent 系统：

1. 用户在软件或 iOS 内置聊天中指挥 Hermes。
2. Hermes 读取真实行情、账户、仓位和风险状态。
3. Hermes 将自然语言转化为结构化交易意图。
4. 所有增加风险的动作经过用户确认和确定性风控。
5. Hyperliquid 适配器使用独立 API Wallet 执行真实交易。
6. Hermes 从确认过的交易、明确反馈和复盘中学习用户风格。
7. 候选策略经过历史验证、影子运行、独立模型审核和用户批准后，可在固定授权范围内自动交易。

产品首先按个人版运行，但身份、账户、订单、风险和审计数据从第一天保留用户归属，避免未来升级多用户版时重写核心系统。

## 2. 用户与角色

### 2.1 交易用户

当前只有一个实际用户，拥有以下权限：

- 连接独立 Hyperliquid 交易钱包
- 配置风险参数和实盘白名单
- 指挥 Hermes 分析和交易
- 确认增加风险的动作
- 查看、纠正和删除学习记录
- 批准新的自动交易版本
- 启用、暂停、恢复和关闭自动交易
- 触发 Kill Switch

### 2.2 Hermes Agent

Hermes 可以：

- 分析市场和账户
- 解释用户指令
- 创建交易意图
- 提出仓位、入场、止损和止盈
- 在授权范围内管理自动交易仓位
- 生成交易复盘
- 形成交易风格候选版本

Hermes 不可以：

- 读取或持有签名私钥
- 直接调用 Hyperliquid 签名接口
- 绕过 Go 风控
- 自行扩大白名单、杠杆、风险或资金上限
- 自行批准候选版本
- 修改已经确认的订单快照
- 进行提现、转账或资金划转

### 2.3 独立审核模型

自动开仓时，独立审核模型对 Hermes 的结构化交易方案进行第二次审核。任一模型不可用、输出无效或审核不通过时，不得自动开仓。

审核模型不能代替 Go 风控，也不能接触签名密钥。

## 3. 产品范围

### 3.1 交易市场

- 交易所：Hyperliquid
- 网络：主网实盘
- 产品：永续合约
- 白名单：BTC、ETH、SOL
- 主要分析周期：1h、4h
- 基础数据周期：1m
- 保证金模式：全仓、逐仓

### 3.2 客户端

- 网页交易终端
- Tauri 桌面软件
- 原生 iOS App
- 软件和 iOS 使用同一用户、会话、聊天、确认单和交易结果

正式交易入口是内置聊天和结构化交易界面，不使用 Telegram 作为交易入口。

### 3.3 数据来源

第一版只使用：

- Hyperliquid K 线和成交量
- 最新价格、标记价格和预言机价格
- 最优买卖价
- 资金费率
- 未平仓量
- 账户、仓位、订单和成交数据

第一版不使用外部新闻、宏观、链上、社交情绪、完整 L2 或逐笔成交数据。

## 4. 核心用户流程

### 4.1 指挥交易

```text
用户输入自然语言指令
→ Hermes 获取实时市场和账户状态
→ Hermes 询问可选的交易理由
→ Hermes 生成结构化交易意图
→ Go 风控计算仓位和风险
→ 客户端显示不可修改的确认单
→ 用户点击确认
→ 服务器重新验证行情、账户和风险
→ 发送执行指令
→ Hyperliquid 签名并执行
→ 核对订单、成交、仓位和止损
→ 客户端返回最终状态
```

### 4.2 确认规则

必须确认：

- 开仓
- 加仓
- 反向开仓
- 增加未成交订单数量
- 提高杠杆
- 放宽或取消止损
- 提高风险上限
- 扩大自动交易授权

可以直接执行：

- `reduce-only` 平仓或减仓
- 收紧止损
- 执行止损止盈
- 撤销未成交的开仓订单
- 紧急停止新交易

开仓和加仓的交易确认只需要在已登录设备点击确认，不要求每笔输入设备密码。提高风险上限、启用自动交易和安全暂停后的恢复需要设备密码。

### 4.3 交易确认单

确认单至少包含：

- 交易所、网络和交易账户
- BTC、ETH 或 SOL
- 买入/卖出
- 开仓/加仓/反向开仓
- 市价、GTC 或 Post Only/ALO
- 全仓或逐仓
- 用户指定杠杆
- 数量、名义价值和预计保证金
- 入场价或限价
- 最差允许成交价
- Stop Market 触发价
- 可选止盈
- 预计手续费、资金费和滑点
- 本单预计最大亏损
- 交易后账户总风险
- 预计强平价格
- Hermes 对指令的解释和交易理由
- 风控结果
- 确认单哈希和有效期

确认后，方向、数量、杠杆、价格边界、止损或账户发生变化时，原确认失效。

## 5. 订单与执行

### 5.1 市价单

市价单内部表示为带滑点上限的 IOC：

- 使用实时最优买卖价计算最差允许成交价
- 立即成交可成交部分
- 未成交部分取消
- 部分成交后不自动追价
- 继续完成剩余数量需要新的确认单

### 5.2 限价单

支持：

- GTC
- Post Only/ALO
- 部分成交
- 自定义有效期
- 修改和撤单

用户未指定 GTC 或 ALO 时，Hermes可以提出选择，但必须显示在确认单中；确认后不能自动切换。

### 5.3 杠杆

- 指挥交易时，杠杆必须由用户指定。
- 未指定杠杆时，Hermes必须追问。
- 自动交易启用时，用户为每个币种预先授权杠杆。
- Hermes不能自行提高杠杆。
- 预计强平价格早于止损或安全距离不足时，风控拒绝交易。

### 5.4 仓位计算

用户未明确数量时，Hermes提出入场和止损，Go 风控根据以下数据计算建议仓位：

- 账户净值
- 用户设置的单笔风险
- 入场与止损距离
- 手续费和滑点预算
- 当前 BTC、ETH、SOL 组合风险
- 保证金和杠杆

没有有效止损时不能生成实盘确认单。

## 6. 止损、止盈和仓位保护

### 6.1 强制底线止损

- 每个实际仓位必须有 `reduce-only` Stop Market。
- Stop Limit 可以额外使用，但不能替代 Stop Market。
- 任何部分成交都必须得到对应数量的保护。
- 加仓前，现有仓位必须处于 `PROTECTED`。
- 止损使用标记价格触发。

### 6.2 保护失败

如果成交后无法确认止损真实存在：

1. 查询真实仓位与活动订单。
2. 有限次数快速重试创建保护。
3. 仍失败时标记 `PROTECTION_FAILED`。
4. 立即使用 `reduce-only` 紧急平仓。
5. 核对仓位归零或记录剩余风险。
6. 发送最高级别告警。

紧急平仓不需要再次确认。

### 6.3 止盈

止盈是可选的，支持：

- 不设置止盈
- 单一止盈
- 多目标分批止盈
- 按仓位比例减仓
- 持仓后增加、修改或取消止盈

所有止盈必须 `reduce-only`。部分止盈后，系统同步缩小剩余止损保护数量；全部止盈后，撤销无效保护订单。

### 6.4 移动止损

指挥交易模式下，只有用户明确指挥后才移动止损。

- 收紧止损：直接执行
- 移到保本、前高/前低或指定价格：直接执行，但显示最终价格
- 放宽止损：生成确认单
- 更新失败：保留旧止损

自动交易模式下，已批准策略可以自动收紧止损、保本、分批止盈、减仓和平仓，但不能自动放宽止损。

## 7. 风险中心

用户可配置：

- 单笔最大风险
- 账户总持仓风险
- 单日和单周最大亏损
- 每个币种最大仓位
- 每个币种最大杠杆
- 最大同时持仓数量
- 单方向最大总敞口
- 最大加仓次数
- 自动交易可用资金
- 自动交易单笔上限
- 连续亏损暂停阈值
- 滑点上限
- 强平与止损最小安全距离

风险设置必须版本化。降低风险立即生效；提高风险需要设备密码。已有仓位超过新限额时，禁止继续加仓，但不擅自强平。

达到风险条件后的动作按策略配置，默认暂停新开仓并继续管理已有仓位。连续亏损达到阈值后暂停，必须由用户手动恢复。

## 8. 行情和账户同步

### 8.1 数据周期

- 保存 1m 基础 K 线
- 确定性生成 1h 和 4h K 线
- 自动开仓只使用已收盘 K 线
- 4h 用于方向上下文
- 1h 收盘后产生一次正式自动交易判断

同一根 1h K 线只能产生一次正式决策。止损、止盈和紧急风险持续运行，不等待收盘。

### 8.2 断线和核对

WebSocket 用于实时数据，Info API 用于启动、重连和周期性核对。

断线后：

- 标记账户数据 `STALE`
- 禁止增加风险
- 重新获取仓位、订单和成交
- 按 `oid`/`cloid` 核对
- 一致性通过后恢复 `LIVE`

下单超时不能直接视为失败，必须进入 `UNKNOWN_REQUIRES_RECONCILIATION` 并先查询真实订单状态。

## 9. Hermes 聊天与模型

### 9.1 内置聊天

支持：

- 市场讨论
- 查询账户、仓位、订单和盈亏
- 自然语言交易指令
- 内嵌交易确认卡
- 实时订单和成交更新
- 交易复盘
- 用户纠正和反馈
- 真实、模拟和假设讨论的明确区分

### 9.2 多模型

- Hermes 支持多个模型和 API 提供商。
- 自动开仓采用“交易模型提出、独立模型审核”。
- 任一模型失败、超时或输出无效时不自动开仓。
- 所有输出必须符合结构化 Schema。
- 已确认订单不能因模型切换而改变。

### 9.3 决策方式

Hermes 输出结构化信号，确定性程序验证：

- 数据是否新鲜
- 品种是否在白名单
- 1h/4h 数据是否完整且已收盘
- 账户和仓位是否一致
- 交易是否符合授权策略
- 是否通过硬风险限制

模型不能以自由文本直接触发签名。

## 10. 学习、自我进化与复盘

### 10.1 可学习数据

只有以下数据可以进入学习集：

- 用户确认并执行的真实交易
- 用户明确标记的模拟交易
- 用户对建议的接受、拒绝或修改
- 用户明确提交的交易理由
- 用户确认的交易后复盘

普通聊天不自动进入学习集。

### 10.2 交易前理由

每次开仓前，Hermes简短询问交易理由，但允许跳过。系统保留原始表达并生成可纠正的结构化标签。

### 10.3 交易后复盘

仓位完全结束后，Hermes自动生成复盘并请求用户反馈。复盘不得以单笔盈亏代替对执行质量和规则一致性的判断。

### 10.4 双模型演进

系统分开维护：

- 交易风格模型：学习并复现用户习惯
- 改进研究模型：离线研究可能的改进

改进不能直接进入实盘。候选版本必须满足用户配置的最少样本、影子周期和风险指标，再由用户批准。

运行中的实盘模型不能在线修改自己。每笔交易必须记录使用的模型、提示词、策略和风险配置版本，并支持回滚。

## 11. 自动交易

### 11.1 授权

自动交易授权持续有效，直到用户关闭或系统安全暂停。授权绑定：

- 交易账户
- 策略与模型版本
- BTC、ETH、SOL 子集
- 每个币种的预授权杠杆
- 风险、资金、订单和加仓范围
- 允许的仓位管理动作

扩大授权需要设备密码和新授权哈希。

### 11.2 自动判断

- 4h 已收盘数据提供方向依据
- 每根 1h K 线收盘后最多一次开仓判断
- 交易模型提出、独立模型审核
- Go 风控最终裁决
- 任一依赖失效时不新开仓

### 11.3 安全暂停

以下情况暂停新开仓：

- 达到风险或连续亏损限制
- 行情或账户数据过期
- 订单状态无法核对
- 止损保护异常
- 签名、数据库或消息系统异常
- 模型连续输出无效
- Kill Switch

条件恢复后不能自动继续。用户必须查看恢复报告并使用设备密码手动恢复。

## 12. 身份、设备和通知

### 12.1 身份

- 当前为个人账户
- 数据模型保留 `user_id`、`account_id` 和所有权检查
- 新设备与设备丢失恢复只使用账户密码
- 账户密码必须强哈希、限速、防爆破并支持会话撤销

设备密码只由操作系统验证，用于提高风险、自动交易启用和安全恢复；应用不读取或保存设备密码。

### 12.2 通知

支持：

- 软件内通知
- iOS Push
- Email

最高级别告警包括：

- 止损保护失败
- 紧急平仓
- 订单结果未知
- 数据长时间不一致
- 风险暂停
- API Wallet 或签名服务异常
- 自动交易被暂停

## 13. 图表和客户端体验

图表支持：

- 1h、4h 及基础周期
- 趋势线和支撑阻力
- 常用指标
- 入场、成交、加仓、减仓和退出标记
- 止损和止盈标记
- Hermes 市场结构与分析叠加
- 实际计划与复盘对比

客户端不得自行计算最终订单风险或签名。展示数据必须标记更新时间、数据状态和来源。

## 14. 非功能需求

### 14.1 可靠性

- PostgreSQL 是唯一交易真相。
- NATS JetStream 用于至少一次事件传递。
- 所有消费者必须幂等。
- Redis 第一版不作为必需组件，不存储关键交易状态。
- 服务重启后能从数据库和 Hyperliquid 重建状态。

### 14.2 安全

- 主钱包不进入系统。
- 独立交易钱包只持有计划交易资金。
- 独立 API Wallet 与签名服务。
- 最小工具权限和网络访问。
- 机密不进入代码、数据库明文、日志或模型上下文。
- 所有增加风险的动作可追溯。

### 14.3 容灾

- 初始使用一台高质量 Linux 服务器和远程加密备份。
- 目标 RPO 不超过 1 分钟。
- 目标 RTO 不超过 15 分钟。
- 单服务器下该目标是工程目标而非保证 SLA。
- Hyperliquid 真实状态必须在恢复后重新核对，不能只恢复本地快照。

### 14.4 可观测性

必须具备日志、指标和链路追踪，覆盖：

- 行情与账户数据新鲜度
- WebSocket 重连
- 下单、确认和签名延迟
- `UNKNOWN_REQUIRES_RECONCILIATION`
- 止损覆盖率
- NATS 重投与幂等命中
- 数据库和备份状态
- 模型调用、审核和输出验证

## 15. 成功标准

产品只有在以下条件同时满足时，才可以称为完成：

- 用户可以在内置聊天中指挥真实交易。
- 增加风险的动作不会绕过确认和风控。
- BTC、ETH、SOL 之外无法实盘下单。
- Hermes 和客户端无法读取签名密钥。
- 订单超时、重复消息和服务重启不会造成重复下单。
- 每个持仓数量都有经过核对的 Stop Market 保护。
- 保护失败会自动降低风险并告警。
- 学习数据可追溯、可纠正、可删除。
- 候选版本不能未经批准进入自动实盘。
- 自动交易的授权、暂停和恢复行为可验证。
- 网页/桌面与 iOS 看到一致的订单和仓位状态。
- 备份恢复后能与 Hyperliquid 真实状态重新一致。
