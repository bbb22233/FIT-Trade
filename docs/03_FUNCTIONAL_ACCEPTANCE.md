# 功能与验收标准

## 1. 验收原则

功能通过不只意味着“正常路径能运行”，还必须证明：

- 增加风险无法绕过确认。
- 模型、客户端和消息重投不能重复下单。
- 网络超时不会被误判为失败。
- 止损保护在部分成交、重启和断线后仍成立。
- 自动交易不能扩大自己的授权。
- 恢复备份后能够与 Hyperliquid 真实状态一致。

每个验收必须保留机器可读结果、版本、时间、输入和失败证据。

## 2. 身份与设备

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| AUTH-001 | 账户登录 | 正确密码可登录；错误密码限速；密码和哈希不出现在日志。 |
| AUTH-002 | 多用户数据边界 | 任意替换 `user_id`、`account_id` 或对象 ID 均无法读取或修改其他归属数据。 |
| AUTH-003 | 新设备 | 仅正确账户密码可登记；登记产生独立设备记录和会话。 |
| AUTH-004 | 会话撤销 | 撤销后所有客户端和 WebSocket 在限定时间内失效。 |
| AUTH-005 | 设备认证 | 提高风险、启用自动交易和安全恢复必须通过操作系统设备认证和服务器 Challenge。 |
| AUTH-006 | 普通确认 | 开仓确认不要求设备密码，但必须来自有效会话、已登记设备和一次性确认 nonce。 |

负向测试：

- 重放旧设备 Challenge
- 修改 Challenge 绑定的风险配置
- 使用已撤销设备确认
- 在浏览器伪造 `device_verified=true`
- 并发登录爆破和凭证填充

## 3. 白名单与账户

| ID | 要求 | 验收标准 |
| --- | --- | --- |

| ACC-004 | 永续合约 | 现货或资金划转动作被拒绝。 |
| ACC-005 | 全仓/逐仓 | 两种模式均能正确显示保证金、强平和组合风险。 |

## 4. 聊天与 Hermes

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| AGENT-001 | 内置聊天 | 网页/桌面可进行流式聊天并读取真实账户的只读信息。 |
| AGENT-002 | 工具白名单 | Hermes 只能发现允许的 MCP 工具，不能调用签名、SQL、Shell、提现或转账。 |
| AGENT-003 | 结构化输出 | 无效 JSON、未知字段、超长输入、错误币种和缺失止损均被拒绝。 |
| AGENT-004 | 身份注入 | Hermes 参数不能覆盖服务器注入的用户和账户。 |
| AGENT-005 | 模型切换 | 模型切换不改变已有确认单、Operation 或订单。 |
| AGENT-006 | 双模型 | 自动开仓必须同时存在有效 Proposal 和独立 Review；任一失败产生 `NO_TRADE`。 |

负向测试：

- Prompt Injection 要求读取私钥
- 模型输出伪造“用户已确认”
- 模型直接构造 Hyperliquid Action
- 模型输出 BTC 白名单但 Payload 为其他币种
- 审核模型超时、拒绝或返回格式错误

## 5. 市场数据

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| DATA-001 | 1m 数据 | BTC、ETH、SOL 的 1m 数据连续性可检测，缺口有明确状态。 |
| DATA-002 | 聚合 | 1h、4h 由 1m 确定性生成，边界使用 UTC。 |
| DATA-003 | 收盘状态 | 未收盘 K 线不能进入正式自动开仓决策。 |
| DATA-004 | 数据新鲜度 | 过期行情或私有账户数据阻止增加风险。 |
| DATA-005 | 断线恢复 | WebSocket 断线后重新获取快照并补齐事件；一致前保持 `STALE`。 |
| DATA-006 | 非范围数据 | 不保存完整 L2 和逐笔成交历史。 |

故障注入：

- 丢失一个 1m K 线
- WebSocket 消息乱序、重复和延迟
- 断网后出现账户外手工成交
- 服务时间偏移
- 订阅 Snapshot 与本地事件重复

## 6. 交易意图与确认

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| TRADE-001 | 自然语言意图 | 买卖方向、品种、订单类型、仓位效果、杠杆和止损转为严格 Schema。 |
| TRADE-002 | 缺失杠杆 | 用户未指定杠杆时不能生成可确认订单。 |
| TRADE-003 | 缺失止损 | 没有有效 Stop Market 时不能生成实盘确认单。 |
| TRADE-004 | 确认快照 | 确认绑定所有风险相关字段；任一字段变化导致确认失效。 |
| TRADE-005 | 有效期 | 过期确认不能执行。 |
| TRADE-006 | 重复点击 | 并发或重复点击只产生一个 Operation 和一个订单效果。 |
| TRADE-007 | 风险降低 | `reduce-only` 平仓、减仓和收紧止损不要求交易确认。 |
| TRADE-008 | 风险增加 | 开仓、加仓、提高杠杆和放宽止损必须有有效确认。 |

确认突变测试：

- 确认后修改数量、方向、账户、杠杆、止损或订单类型
- 确认后市场快照过期
- 替换确认哈希中的风险配置版本
- 同一个确认在两台设备同时使用

## 7. 订单执行

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| ORDER-001 | 市价保护 | 市价意图转换为带最差价格的 IOC，未成交部分取消。 |
| ORDER-002 | 不追价 | 部分成交后系统不会自动为剩余部分再次下单。 |
| ORDER-003 | GTC | GTC 可挂单、部分成交、修改和撤销。 |
| ORDER-004 | ALO | ALO 会立即成交时保持取消，不静默变为 GTC。 |
| ORDER-005 | `cloid` | 每个交易订单具有唯一、可查询的 `cloid`。 |
| ORDER-006 | 未知结果 | 请求超时进入 `UNKNOWN_REQUIRES_RECONCILIATION`，查询真实状态前不重试。 |
| ORDER-007 | 消息重复 | NATS 重投、进程重启和响应重复均不产生第二个交易效果。 |
| ORDER-008 | 精度 | 数量、价格、最小名义价值和取整符合交易所元数据。 |

故障注入：

- 请求送达交易所但响应丢失
- 请求未送达但本地超时
- Executor 成功后崩溃、结果未发布
- 结果发布后未收到 Ack
- `cloid` 已存在
- 订单部分成交后取消

## 8. 风险

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| RISK-001 | 仓位计算 | 根据净值、止损距离、费用和滑点确定性计算仓位。 |
| RISK-002 | 定点数 | 金额、价格、数量和风险计算不使用二进制浮点作为权威结果。 |
| RISK-003 | 组合风险 | 全仓模式下 BTC、ETH、SOL 的仓位和活动订单共同参与计算。 |
| RISK-004 | 强平距离 | 止损在强平之后或距离不足时拒绝。 |
| RISK-005 | 配置版本 | 每个 Operation 绑定实际使用的风险版本。 |
| RISK-006 | 提高风险 | 提高限额需要设备认证；Hermes 无权修改。 |
| RISK-007 | 达到上限 | 按策略暂停或退出；默认禁止新开仓并继续保护已有仓位。 |
| RISK-008 | 连续亏损 | 达到用户阈值后暂停，不能自动恢复。 |

## 9. 止损与保护

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| PROTECT-001 | 强制 Stop Market | 任意非零仓位都有对应 `reduce-only` Stop Market。 |
| PROTECT-002 | 部分成交 | 每次部分成交后，在限定时间内更新保护数量。 |
| PROTECT-003 | 加仓门槛 | 未处于 `PROTECTED` 时无法继续加仓。 |
| PROTECT-004 | 替换安全 | 修改止损失败时旧止损仍有效。 |
| PROTECT-005 | 减仓同步 | 减仓或止盈后保护数量不超过产生反向风险的范围。 |
| PROTECT-006 | 保护失败 | 有限重试失败后自动 `reduce-only` 紧急退出并告警。 |
| PROTECT-007 | 重启核对 | 服务重启后从真实仓位和订单重建保护状态。 |
| PROTECT-008 | 放宽止损 | 放宽或取消底线止损必须确认。 |

对抗场景：

- 父订单部分成交后取消
- 止损创建响应丢失
- 旧止损撤销成功、新止损创建失败
- 用户在 Hyperliquid 原生界面手工改仓
- 同币种快速连续部分成交
- Stop Market 部分成交

## 13. 安全与秘密

| ID | 要求 | 验收标准 |
| --- | --- | --- |
| SEC-001 | 主钱包隔离 | 代码、配置、日志、数据库和备份中不存在主钱包密钥。 |
| SEC-002 | Executor 隔离 | 只有 Executor 可以解封 API Wallet。 |
| SEC-003 | 网络最小化 | Executor 无公网入站，Hermes不能连接 Executor。 |
| SEC-004 | Action 白名单 | 提现、转账、资金划转和任意原始签名请求被拒绝。 |
| SEC-005 | 日志防泄露 | 私钥、账户密码、模型 API Key 和完整敏感 Payload 不出现在日志和错误中。 |
| SEC-006 | 轮换 | 新 API Wallet 启用、旧 Wallet 撤销后，旧签名请求不可继续执行。 |

秘密扫描必须覆盖：

- 源码和 Git 历史
- 容器镜像
- 配置模板
- 日志样本
- 备份清单
- 模型输入输出

## 15. 发布门槛

### 15.1 小额主网指挥交易

必须满足：

- 所有契约、风控、幂等和止损负向测试通过
- 主网只读同步通过持续观察
- API Wallet 和资金上限已人工核对
- Kill Switch 已实测
- 备份和恢复演练完成
- 用户给予一次明确的小额主网执行授权

用户选择直接小额主网，不代表可以省略这些工程验证。

### 15.2 正常指挥交易

必须额外满足：

- 多次小额订单、部分成交、撤单和止损证据
- 未知结果核对路径已在受控场景证明
- 无未解决的高严重度问题
- 告警和审计完整

### 15.3 自动交易

必须额外满足：

- 候选版本达到用户配置的最少样本与影子周期
- 独立审核模型链路稳定
- 自动授权和设备恢复流程通过
- 1h 唯一决策和不使用未收盘数据通过
- 安全暂停和禁止自动恢复通过
- 真实资金范围获得新的明确授权

## 16. 明确不可接受的“通过”

以下情况不能称为通过：

- 只有单元测试绿色，没有真实协议或故障注入
- Agent 能生成订单文本，但没有确认绑定
- Executor 启动成功，但没有真实订单/账户核对
- 止损请求返回成功，但未查询确认订单存在
- WebSocket 已连接，但本地投影未与快照一致
- 模拟交易盈利，但候选版本没有时间隔离
- 服务恢复运行，但没有与 Hyperliquid 重新核对
- 小额主网成功一次，就宣称自动交易安全
